# Cookbook

Complete, copy-paste examples for the things people actually build. Each recipe starts from the project you built in [Your first panel](../quick-start) and ends with something you can see in game.

Pick the one that looks like your idea:

- **[Talk between the page and the plugin](talk-to-your-plugin)** — buttons, JSON data and callbacks in both directions.
- **[A click-through HUD overlay](hud-overlay)** — a HUD element over the game where only your buttons take clicks.
- **[A controller-friendly menu](controller-menu)** — D-pad navigation and face buttons with your own actions.
- **[Show a 3D item preview](item-preview)** — a real mesh rendered by the game inside your page.
- **[Run game-thread work from a button](run-game-thread-work)** — change game state safely from a page action.
- **[Open a panel from Papyrus](from-papyrus)** — a complete panel without writing C++.
- **[Build a settings page](settings-panel)** — sliders and toggles that save through your plugin.
- **[Translate your interface](translate-your-ui)** — JSON translations that follow the player's game language.
- **[Put a view on an in-world screen](in-world-screen)** — render a page onto a mesh in the world.

If a recipe refers to something you have not set up yet, the linked page explains it. Every recipe is small on purpose — it is a starting point, not a framework of its own.
